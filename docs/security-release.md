# 安全更新部署確認

- 合併後舊登入 Cookie 不再有效，使用者需重新登入一次。資料庫及本機收藏、觀看紀錄不會清除。
- `auth` 改為 HttpOnly、正式環境 Secure、七天有效的簽署工作階段，不含密碼。`auth_info` 僅有使用者名稱與顯示角色，API 不接受它作為授權。
- 沿用既有 `PASSWORD` 簽署；變更此密碼會使既有工作階段失效。部署需設定密碼，未設定時不允許登入或註冊。
- Vercel 排程需另設定高強度隨機 `CRON_SECRET`，呼叫 `/api/cron` 時帶 `Authorization: Bearer <CRON_SECRET>`。未設定時會回傳 401，避免匿名觸發。不要將密鑰寫入儲存庫或 URL。
- HttpOnly Cookie 由瀏覽器與 PWA 自動帶入請求，不需提供給網頁程式。使用者選單及按使用者分隔的快取使用顯示 Cookie。
- API 本身驗證工作階段，再查資料庫中的管理員角色；修改顯示 Cookie 不會獲得管理權限。
- HTTPS 頁面上 HTTP 海報改經既有圖片代理。只支援 HTTP 的影片仍可能被瀏覽器阻擋；不自動改寫未知來源網址或更換資料來源。
- 預覽站需確認：一般登入、登出、重新登入、管理員設定、收藏及繼續觀看；使用雲端資料庫時另檢查一般使用者權限。正式部署仍需 PR 審查與必要 CI。
- 此次不加入分散式登入限速或重構資料庫與播放器，聚焦工作階段與 API 邊界。
