# 換頁效能與快取維護

## 改善內容

- 頂部快速搜尋透過 Next.js router 切換頁面，不再以一般表單重載整份文件。JavaScript 尚未就緒時，仍保留原表單 GET 搜尋。
- 根路由提供符合莫蘭迪布景的載入回饋。這是介面回饋，不表示外部來源請求本身加速。
- 首頁電影、影集、綜藝各自載入與顯示；其中一個來源緩慢或失敗，不會隱藏其他已完成區塊。
- 桌面與手機選單共用進行中的版本檢查。成功結果保留十分鐘，失敗與不合法的版本內容不保留。
- 豆瓣分類與自訂片單的成功結果在瀏覽器記憶體保留一分鐘，最多 24 筆，並合併同時發出的相同請求。返回列表可沿用短期資料。

## 快取邊界

共用工具位於 `src/lib/request-cache.ts`，只套用於公開版本資訊與公開豆瓣片單。不得擴大到登入、帳號權限、收藏、播放進度、搜尋回應或實際媒體網址。

片單快取鍵包含請求類型、實際代理網址、分類／標籤、影片類型、頁數與筆數。代理設定改變時使用不同快取項目。失敗回應不保留，進行中請求過了有效期限也可重新嘗試。

記憶體快取在重新整理或關閉分頁後消失；沒有將資料寫入 localStorage、IndexedDB 或 PWA Service Worker。伺服器端片單呼叫不啟用這個快取。既有 `/api/` 與導覽的 PWA NetworkOnly 規則保持不變。

## 測試與驗收

自動測試包含站內搜尋、空白輸入、同時請求去重、TTL 到期、失敗重試、容量上限、代理／頁碼分流，以及首頁快區塊不等待慢區塊。執行 `pnpm test --runInBand`、`pnpm lint`、`pnpm typecheck`、`pnpm build`。

預覽人工驗收：

1. 從頂部搜尋「龍貓」，確認站內切換及繁簡搜尋正常。
2. 開啟電影列表，切至另一頁再於一分鐘內返回；在瀏覽器 Network 比較同一分類請求是否重複。超過一分鐘則應重新查詢。
3. 開啟首頁，確認電影、影集、綜藝分別顯示；可用開發工具減速，觀察較快區塊先出現。
4. 在十分鐘內切換多個頁面，觀察 VERSION.txt 不再因兩個選單重複讀取。
5. 改變豆瓣代理設定後再開同一片單，確認沒有重用其他代理的資料。
6. 確認收藏、登入、PWA、深色模式與播放功能維持正常。

以同一裝置、同一網路及相同頁面比較冷啟動與返回列表的時間、請求數和點擊回饋。模擬測試只證明行為，不是正式站效能量測；尚未量測前不宣稱節省百分比或所有來源變快。
